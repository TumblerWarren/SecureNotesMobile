# Vault transfers

- Successful file/folder imports are read back through authenticated decryption and compared to the source with SHA-256 before offering deletion. The user selects and confirms originals. Both copies are rechecked immediately before requesting provider deletion. Unsupported/read-only providers keep originals; the result reports failures. No source directories are recursively deleted. Provider deletion is not secure erasure and cannot remove cloud trash, backups or prior copies. Providers do not offer a universal atomic compare-and-delete operation.
- Export copy is available on an item's menu and the selection toolbar after unlocking. Binary files retain their filename and MIME type. Multiple selections produce ZIPs. Notes export as structured JSON plus complete drawing stroke data and decrypted attachments in ZIPs. These are portable structured exports, not rendered PDF documents. Export streams directly to the user-selected destination without plaintext staging files. Failed destination documents are removed where supported; a provider or process crash can leave a partial external document.
- Settings > Encrypted backup saves a ciphertext-only snapshot through ACTION_CREATE_DOCUMENT. Android cloud document providers may be destinations. There is no scheduled sync or provider-specific login. The writer lease prevents database/WAL mutation during the snapshot. SQLCipher protects note text, metadata and keys; Tink streaming AEAD protects each object. HMAC-SHA256 with a domain-separated vault key authenticates the ordered archive inventory and ciphertext digests, preventing silent removal/reordering of entries. Archive metadata exposes ciphertext object IDs, sizes and counts, but not original names or note contents.
- Welcome > Restore encrypted backup installs into an empty vault only. It supports the backup-time password or its recovery key plus a new password. Restore extracts only approved relative paths to a private ciphertext staging directory, authenticates the archive before opening its database, checks SQLite integrity, and reads every object through authenticated decryption before atomic installation. Rejected backups leave the existing destination untouched. Current defensive limits: 100,000 entries and 1 TiB extracted ciphertext; available disk space can impose lower limits. Staging is removed on handled failures; process termination can leave ciphertext staging files.
- Password changes do not re-encrypt historical backups. Keep the backup-time password or recovery key. Back up to an independent location and test restore before deleting a device's vault. Deletion of app storage removes local vault data.
